# 글로벌 리더보드 및 닉네임 시스템 구현 계획

사용자의 최고 뒤집기 기록을 기준으로 순위를 겨루는 통합 글로벌 리더보드, 첫 접속 시 중복 불가 닉네임 필수 등록 흐름, 그리고 설정 내 닉네임 변경 기능을 추가합니다.

---

## User Review & Critical Decisions

> [!IMPORTANT]
> **확정된 요구사항 및 확인 사항**
> - **사용자 식별**: 별도 로그인 없이 브라우저 고유 식별자 + **중복 불가 닉네임** 기반 간편 등록 (1인 1랭킹 유지).
> - **첫 접속 닉네임**: 최초 접속 시 닉네임 입력이 필수이며, 기존 사용자와 중복되는 닉네임은 사용할 수 없습니다.
> - **리더보드 표시 항목**: `순위`, `닉네임`, `최고 뒤집기 수`, `랭크`를 난이도 구분 없는 **단일 통합 리더보드**로 제공합니다.
> - **진입 및 변경 경로**: 상단 랭크 버튼 왼쪽에 **시상식(포디움) 아이콘**을 배치해 리더보드를 열고, **소리 설정** 탭 하단 여백에 닉네임 변경 영역을 배치합니다.

- **Firebase Firestore 연동 필요**: 여러 사용자의 최고 기록을 실시간·영구적으로 공유하고 닉네임 중복을 검사하려면 클라우드 데이터베이스(Firestore) 프로비저닝이 필요합니다. 계획 승인 후 Firebase 설정 승인 단계가 진행됩니다.
- **비로그인 기반 보안 트레이드오프**: 로그인 없이 닉네임을 등록하므로 계정 인증 토큰 대신 클라이언트 고유 ID와 Firestore 보안 규칙(닉네임 선점 잠금, 점수 범위·형식 검증, 타인 닉네임 점유 차단)으로 데이터를 보호합니다.

## 1. Overview & Core Concept

- **핵심 기능**: 모든 플레이어의 개인 최고 뒤집기 기록(`bestFlips`)을 기준으로 하나의 통합 리더보드를 운영합니다. 한 사용자는 단 하나의 순위 항목만 보유하며, 더 높은 점수를 달성할 때마다 기존 기록이 갱신됩니다.
- **대상 사용자**: 별도의 회원가입 절차 없이 닉네임만 정해 즉시 AI 대결을 즐기고 다른 플레이어와 타자 실력을 비교하고 싶은 이용자.
- **기대 효과**: 개인 최고 기록 확인에서 나아가 전체 사용자 간 순위 경쟁 동기를 부여하며, 기존 Monkeytype 스타일의 미니멀한 사용성을 해치지 않습니다.

## 2. User Experience & Visual Design

### 주요 사용자 흐름

1. **최초 접속 (닉네임 온보딩)**
   - 저장된 플레이어 식별 정보/닉네임이 없으면 게임 시작 오버레이보다 먼저 닉네임 설정 모달이 표시됩니다.
   - 2~16자(한글, 영문, 숫자, `_`, `-`) 규칙과 실시간/제출 시 중복 검사를 통과해야 입장이 완료되며, 중복 시 인라인 안내 문구를 표시합니다.
2. **리더보드 진입 및 열람**
   - 상단 헤더의 트로피(랭크) 버튼 **왼쪽**에 위치한 시상식(3단 포디움) 아이콘 버튼을 클릭하면 통합 리더보드 모달이 열립니다.
   - 모달에는 **순위 · 닉네임 · 최고 뒤집기 · 랭크** 4개 열만 정갈하게 표시되며, 상위 1~3위는 테마 강조 색으로 구분되고 본인 행은 별도로 강조됩니다.
3. **최고 기록 자동 반영**
   - 60초 대결 종료 시 이번 판 뒤집기 개수가 본인 기존 최고 기록을 경신하면, 로컬 기록과 함께 원격 리더보드 점수와 랭크가 자동 업데이트됩니다.
4. **닉네임 변경 (소리 설정 탭 하단)**
   - **설정 → 소리 설정** 탭의 효과음 설정 아래 빈 공간에 **닉네임 변경** 구역이 배치됩니다.
   - 새 닉네임 입력 후 저장 시 중복 여부를 검사하며, 통과하면 기존 닉네임 점유를 해제하고 새 닉네임으로 리더보드 항목을 그대로 이어받습니다(점수 유지, 1인 1랭킹 유지).

### 시각적 일관성 및 디자인 원칙

- **Aesthetic Direction**: 기존 앱의 Monkeytype 스타일 미니멀리즘과 현재 선택된 8종 테마 토큰(`bg`, `surface`, `surfaceElevated`, `border`, `text`, `muted`, `accent`)을 그대로 따릅니다.
- **Typography & Tabular Discipline**: 순위, 뒤집기 수, 랭크 티어는 모두 고정폭 숫자 정렬(`tabular-nums`)과 선택된 사용자 글꼴(`--typing-font`)을 적용해 세로 줄 맞춤을 유지합니다.
- **Podium Icon Button**: 헤더 우측 랭크(트로피) 버튼 바로 왼쪽에 동일한 크기(`40px × 40px`)와 라운딩을 갖춘 깔끔한 3단 시상식 선형 아이콘 버튼을 배치합니다.
- **States**: 리더보드 불러오기 중 로딩 상태, 등록된 기록이 없을 때의 빈 상태, 네트워크/권한 오류 시 재시도 안내 상태를 모두 포함합니다.

## 3. Key Product Decisions & Trade-Offs

- **결정 1: 로그인 없는 1인 1랭킹 및 닉네임 중복 방지 구조**
  - *선택한 방식*: 브라우저별 고유 `playerId`(UUID)를 로컬에 생성해 리더보드 문서 키로 사용하고, 별도의 `nicknames` 인덱스 컬렉션을 두어 Firestore 트랜잭션으로 닉네임 선점 및 변경을 원자적으로 처리합니다.
  - *이유*: 로그인을 요구하지 않으면서도 동일 사용자가 닉네임을 바꿀 때마다 리더보드에 중복 행이 쌓이는 문제를 원천적으로 방지하고, 동시에 두 사람이 같은 닉네임을 선점하지 못하게 합니다.
  - *대안 비교*: `nickname` 자체를 리더보드 문서 키로 쓰는 방식은 구현이 단순하지만, 닉네임 변경 시 점수 이관 중 동시성 충돌이나 기존 기록 유실 위험이 있어 분리 인덱스가 더 안전합니다.

- **결정 2: 난이도 통합 단일 리더보드**
  - *선택한 방식*: AI 타수(200/400/600/800타)와 무관하게 사용자의 최고 뒤집기 개수를 단일 순위표로 정렬합니다.
  - *이유*: 기존 랭크 시스템(`E`~`L을가져가`) 역시 순수 뒤집기 개수를 기준으로 하므로, 통합 리더보드가 랭크 체계와 일관성이 높고 비교가 직관적입니다.

- **결정 3: 데이터 저장소 선택**
  - *선택한 방식*: Firebase Firestore (실시간/서버 쿼리 지원, 규칙 기반 무결성 검증).
  - *이유*: 클라이언트 SPA 환경에서 별도 백엔드 서버 유지 없이 여러 사용자의 기록을 안전하게 공유하고 상위 순위 정렬 조회를 즉시 지원할 수 있습니다.

## 4. Technical Architecture & Data Strategy

### 시스템 및 데이터 흐름

```
┌────────────────────────────────────────────────────────────────────┐
│                        클라이언트 애플리케이션                       │
│                                                                    │
│  ┌──────────────┐   ┌────────────────────┐   ┌──────────────────┐  │
│  │ 첫 접속 모달 │   │  상단 시상식 버튼  │   │ 소리 설정 탭 하단 │  │
│  │ (닉네임 등록)│   │  → 리더보드 모달   │   │  (닉네임 변경)   │  │
│  └──────┬───────┘   └─────────┬──────────┘   └────────┬─────────┘  │
│         │                     │                       │            │
│         └─────────────────────┼───────────────────────┘            │
│                               ▼                                    │
│                 ┌──────────────────────────┐                       │
│                 │   리더보드 서비스 계층     │◀── 게임 종료 시      │
│                 │ (트랜잭션/점수 동기화)    │    신기록 자동 반영   │
│                 └─────────────┬────────────┘                       │
└───────────────────────────────┼────────────────────────────────────┘
                                │
                                ▼
┌────────────────────────────────────────────────────────────────────┐
│                        Firebase Firestore                          │
│                                                                    │
│  ┌──────────────────────────────┐  ┌────────────────────────────┐  │
│  │ leaderboard/{playerId}       │  │ nicknames/{nicknameKey}    │  │
│  │ - playerId, nickname         │  │ - playerId, nickname       │  │
│  │ - nicknameKey, bestFlips     │  │ (대소문자 무시 중복 잠금)   │  │
│  │ - rank, updatedAt            │  │                            │  │
│  └──────────────────────────────┘  └────────────────────────────┘  │
└────────────────────────────────────────────────────────────────────┘
```

### 데이터 모델 및 상태 매핑

- **로컬 플레이어 상태**: `playerId`(UUID), `nickname`을 브라우저 저장소에 유지해 재방문 시 동일 사용자로 자동 인식합니다.
- **리더보드 엔트리**: `playerId`, `nickname`, `nicknameKey`(소문자 정규화), `bestFlips`(정수), `rank`(자동 산출 등급), `updatedAt`으로 구성되며 `bestFlips` 내림차순(동점 시 먼저 달성한 순)으로 정렬합니다.
- **닉네임 중복 방지 잠금**: `nicknames/{nicknameKey}` 문서를 트랜잭션으로 검사·생성·해제하여 중복 닉네임 등록을 차단하고, 닉네임 변경 시 이전 잠금을 해제한 뒤 새 잠금을 확보합니다.
- **에러 및 복구 처리**: Firestore 연결 확인 및 구조화된 에러 핸들러를 적용해 오프라인/권한/중복 충돌 발생 시 사용자에게 명확한 안내와 재시도 동작을 제공합니다.
